## ざっくり全体像

バーチャルライブの個人制作・個人検証として、Unity、照明、モキャプ、フェイシャル、カメラ、VJ、AE、現場運用まで、必要そうなものを片っ端から検証しているログ。

最初はArtNetで灯体を動かすところから始まって、だんだん「ライブは技術デモじゃなくて、主役のアクトと音楽をどう成立させるか」という方向に寄っていく。

技術ログとしても濃いけど、むしろ制作思想の変化がかなり大事。

## 2024-04 から 2024-06

### ArtNet / DMX / 灯体制御の始まり

- MaterialPropertyBlockで灯体の発光や色を動かす。
- Fogが重いとUpdateが引っかかっているように見える。
- 全体Fogではなく、ライト側のvolumetric multiplier的なもので調整する方針。
- ArtNetChannelsReceiverやRGBWLightController系の実装。
- MovingLight、PAR lightのパッチ設計。
- Avolites / TouchDesigner / ArtNet送出の検証。
- Unity内にReceiverを置いて参照するのがつらくなり、Prefabにコンポーネントをつければ動く方向へ。

記事候補:

- UnityでArtNetを受けて灯体Prefabを動かすメモ
- ArtNet Receiverをシーン参照からPrefab完結にした話
- FogとVolumetric Lightをライブっぽく扱うときのメモ

## 2024-06 から 2024-07

### VLiveKitっぽい方向

- ArtNetサーバーをIP/Portごとに共有する実装。
- 同じポートを複数コンポーネントから指定してもバグらないようにする。
- DMX REC機能を復活させたい。
- ArtNetで照明だけでなく、カメラ、エフェクト、LED、任意のパラメータを制御する発想。
- Unityは信号を受けるレンダリングマシンとして扱う方向が出てくる。

記事候補:

- UnityでArtNet受信用サーバーを共有する設計メモ
- DMX RECをUnityでやりたい理由
- バーチャルライブでReceiver系Prefabが増えすぎる問題

## 2024-07 から 2024-08

### VFXGraph / 特効 / ステージ小物

- VFXGraphでスパークラー、CO2、煙、火花、炎、ケーブル系を試す。
- 特効はDMX制御が普通にある。
- CO2、ファイアボール、スモーク、スパークラーの挙動差を調べる。
- ケーブル、マイク、スピーカー、アンプ、クレーンカメラ、幕など、ライブ小物を作る方向へ。
- ライブ映像をUnityで模写する方針。

記事候補:

- VFXGraphでライブ特効っぽいものを作るメモ
- CO2とスモークとファイアボールの挙動差をCGで考える
- バーチャルライブで効く小物リスト

## 2024-08 から 2024-09

### アニメーション / ポージング / フェイシャル

- Blenderでポージング、リグ、MMD/VRM変換を試す。
- 「決めカット」と「そのつなぎの柔らかさ」が重要という知見。
- 4秒から5秒尺のアニメーションは、1秒ごとの決めカットと余韻で成立しやすい。
- フェイシャル、特に下瞼、口の横幅、まつ毛、視線が重要。
- 顔とポーズが品質上限を決める、というメモが何度も出る。
- KPOPの評価基準を、キャラクターパフォーマンス評価に転用する発想。

記事候補:

- ライブ用キャラモーションで「決めカット」が大事だと思ったメモ
- フェイシャルがないと寄りカメラが映えない問題
- KPOP評価基準をバーチャルライブのアクトに持ち込むメモ

## 2024-09 から 2024-10

### MVR / VectorWorks / MagicQ CSV / 配灯再現

- VectorWorksやMVRから灯体位置を取り出し、Unity上に再現する方向。
- MagicQのCSV形式を調べる。
- MVRをBlenderに読み込んで、FBXとしてUnityに持っていく。
- 位置、回転、灯体種別、パッチ情報をもとに、ArtNet仕込み済みPrefabに置換する仕組み。
- 「ステージ全体を自分で作るより、プロの配灯やステージ設計の力を借りる」方向へ。

記事候補:

- MVRからUnityに配灯を持ってくるメモ
- MagicQ CSVからArtNet灯体Prefabを配置する
- VectorWorksの図面をUnityライブシーンに使うまで

## 2024-11 から 2024-12

### 現場運用 / Timecode / Unityはレンダリングマシン

- UnityでLTCを直接読むより、外部でTime変換してOSCなどでUnityに渡す方が良さそう。
- TouchDesignerで信号を見てからUnityへ渡す発想。
- Unityはなるべくレンダリングに徹し、ArtNet、OSC、Timecode、NDIを外部から受ける。
- 音、モーション、フェイシャルがキャラクターライブの根っこ。
- シェーダやエフェクトは大事だけど、主役のアクトが弱いとライブとして弱い。

記事候補:

- Unityをライブのレンダリングマシンとして扱うメモ
- LTCをUnityで直接読まない方が良さそうと思った理由
- バーチャルライブで音・モーション・フェイシャルが軽視されがちな問題

- 照明卓、ArtNet、図面、ネットワーク機材など、既にライブ業界で解決されているものをちゃんと使う。
- 自宅にモキャプや検証環境を作る発想。
- バーチャルライブの個人制作・個人検証コミュニティとしてVLiveHouse!!!を育てたい。
- Zennや記事化の必要性が出てくる。

記事候補:

- 自宅にライブ検証環境がほしい理由
- Unity + ライブ用語で自分の雑メモが検索に出てくる問題

## 2025-04 から 2025-06

### HDRP / MToon / VRM / MMD / キャラルック

- MToonをHDRP互換に寄せる検証。
- VRMをHDRPにインポートし、元のルックをなるべく維持する。
- MMDMechanimのシェーダをMToonへ変換。
- 法線球面化、ライト方向制限、レンブラントライティング、視野角打消し、HairShadowなど。
- ライブ照明とキャラルックの両立がテーマ。

記事候補:

- HDRPでVRM/MToonっぽいルックを扱うメモ
- Toonキャラがライブ照明で壊れないようにするためにやったこと
- 法線球面化とHairShadowで顔ののっぺり感を減らす

## 2025-07 から 2025-09

### キャラデザイン / AE / 実写合成 / コンポジット

- チェンソーマン、ゼンゼロ、タコピー、MAPPA系のルック研究。
- 今風のキャラ、まつ毛、唇、瞳、鼻、髪色などの整理。
- AE、ライトラップ、グレイン、色収差、マスク、メッシュワープ、タイポなど。
- 実写背景にUnityでレンダリングしたキャラ素材を合成する発想。
- 「ライブ照明をやりたいだけでは足りなくて、主役を成立させる画作りも必要」という流れ。

記事候補:

- Unityキャラ素材をAEで合成してみるメモ
- 実写合成でキャラを馴染ませるときに見たポイント

## 2025-10 から 2025-12

### 制作態度 / フェイシャルセレクター / Timecode同期 / HDRP拡張

- 複雑な原因を探す前に、普通に報連相や段取りが大事という反省。
- ライブで「大事にされている感」が伝わることが重要。
- 揺れもの、スキニング、めり込みは減点が大きい。
- フェイシャルセレクター、左右非対称シェイプ、下瞼、口、ハイライト制御。
- TimecodeでUnityと照明卓を同期。
- HDRPでカスタムライト、動的面光源、プロジェクション、HairShadow、ステンシル、Custom Passなどを検証。

記事候補:

- 個人制作・個人検証で複雑性バイアスにハマりがちな話
- キャラライブで「雑に扱われてる感」が出るポイント
- Unityと照明卓をTimecode同期したメモ
- HDRP Custom PassでToon向けのカスタムライトを作るメモ

## 2026-01 から 2026-03

### Recorder / MagicQ / ArtNet TC / 効率化

- Unity Recorderの映像開始フレーム、音ズレ、頭フレーム重複問題を検証。
- 音はDSP Time、映像はGame Timeで基準が違うため完全一致が難しい。
- RecorderClip直前にTimelineをEvaluateする、音をプリロードするなどで詰める。
- ArtNet TimecodeをTouchDesignerで受ける/送る。
- MagicQのBPM sync、FX preset、プレイバック再利用で照明作業が速くなる。
- 納品前は、加点より減点回避の修正が重い。

記事候補:

- Unity Recorderで音と映像をフレーム単位で合わせようとしたメモ
- ArtNet TimecodeをTouchDesignerで扱ったメモ
- MagicQで照明作業を速くするために見たところ
- 素材のフレーム基準が曖昧だと後工程で全部つらい

## 繰り返し出てくる思想

- Unityで全部やろうとしない。
- ライブ業界で既にあるものは使う。
- 技術的にすごいことと、ライブとして良いことは別。
- 主役を食う背景、エフェクト、照明は危険。
- フェイシャル、肩、視線、口、揺れもの、めり込みは減点が大きい。
- 観客に伝わらない深読みオマージュより、パッと見て鮮やかで楽しい方が強い。
- シェーダやポスプロは大事だが、演者のアクトと音楽理解が弱いとライブにならない。
- 納品前の問題は、高度な技術問題ではなく、段取り、検証不足、基準の曖昧さで起きがち。
- 検証環境と自腹機材は、長期的にはかなり効く。
